# 验证样例

## 初始数据

使用嵌入式模式首次启动时，应用自动导入四份原创示例资料：

| 资料 | 分类 | 主要内容 |
| --- | --- | --- |
| 混合检索研究笔记.md | 研究方法 | 向量、全文、RRF 与可溯源 |
| Transformer论文导读.md | 论文阅读 | 自注意力、多头注意力与位置编码 |
| 向量索引实验记录.md | 实验记录 | HNSW 参数、召回率与可重复性 |
| 数据库课程笔记.md | 课程笔记 | 索引、事务和隔离级别 |

当前基线验证结果为 4 份资料、20 个文本段落。`AUTO_SEED=false` 时可在界面上传自己的资料。

## 样例一：向量与全文混合检索

1. 打开「检索工作台」。
2. 输入 `混合检索`，不设置分类或文档过滤。
3. 点击「检索资料」。

预期：返回相关段落，首条来源为《混合检索研究笔记》，结果包含章节、正文、标签和来源。

技术证据：后端把查询同时传入 `hybrid_search` 的 `query.where_document` 全文条件和 `knn.query_embeddings` 向量条件，使用 `rank.rrf` 融合排名，见 `backend/app/store.py`。

## 样例二：不同措辞的语义查询

1. 输入 `怎样减少数据库磁盘读写`。
2. 执行检索。

预期：即使资料不一定使用完整查询原句，也能返回讨论索引和 I/O 的内容。

技术证据：查询由本地中文模型转换为 512 维向量，seekdb 使用与写入时一致的向量空间执行近似检索。

## 样例三：结构化条件过滤

1. 输入 `HNSW`。
2. 分类选择「实验记录」。
3. 执行检索。

预期：所有结果均属于「实验记录」，可找到讨论 HNSW 参数和召回率的段落。

技术证据：分类条件同时应用于全文与向量两路查询，而不是在前端对结果做二次过滤。

## 样例四：原文溯源

1. 在任一检索结果中点击「查看原文」。
2. 核对资料标题、章节和所在段落。
3. 查看前后段落，确认上下文含义。

预期：检索结果 ID 能在对应资料的分段列表中找到，来源和章节一致。

## 样例五：资料管理与边界情况

1. 在「我的资料」中上传一份 UTF-8 `.txt` 文件，填写分类和标签。
2. 再次上传相同文件，界面应提示相同内容已经导入。
3. 输入空白检索内容，界面或 API 应拒绝请求。
4. 删除新上传的资料，再次访问其详情应返回 404。

## 自动化核对

应用运行时执行：

```bash
.venv/bin/python scripts/verify_seekdb.py
.venv/bin/python scripts/verify_api_edges.py
```

预期两条命令均输出 `"status": "passed"`。本次实际记录：

- `artifacts/seekdb-verification.json`：混合检索、语义查询、结构化过滤与原文溯源。
- `artifacts/api-edge-verification.json`：上传、重复导入、空查询、删除与删除后 404。
- `artifacts/unit-tests.txt`：解析、切分、编码和输入校验单元测试。
